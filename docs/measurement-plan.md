# Measurement plan

Outputs below were counted from the scripts' own logs. Outcomes (did it make work easier?) are **to be measured**; this is how.

| Indicator | Why it matters | How to measure | Target | Status |
|---|---|---|---|---|
| Time for a newcomer to find 3 common files | Findability is the main promise of the new structure | At the next intake, give 3 newcomers the same 3 file names and a timer; record minutes each | Under 5 minutes | to be measured |
| Files following the naming rule | Shows if the convention survives day-to-day use | Every two weeks, sample the 20 newest files; count names matching the pattern | 80% or more | to be measured |
| Items waiting in the inbox folder | A growing inbox means people do not know where to save | Count items in "01 Inbox" every two weeks (one Drive search) | Stable or falling | to be measured |
| Items not owned by the project account | Files owned by students vanish when they leave | Run `auditOwnership()` once a month; read the REMAINING line | 0 | 0 after migration; monthly checks to be measured |
| Ease of finding files (self-reported) | Captures what counts can't | Average of the 1 to 5 question in the feedback form; response rate = answers ÷ members | 4 or more; 50% response | to be measured |
| Drive Map weekly users | Shows if the tool is used by others | Apps Script "Executions" panel, unique users per week, after deployment | — | to be measured |
| Coordinator time on "where is X?" questions | The time the structure should give back | Coordinator logs these questions for 2 weeks | Falling over time | to be measured |
